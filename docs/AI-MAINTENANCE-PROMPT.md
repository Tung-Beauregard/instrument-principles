# 跨 AI 維護文件補齊指令

用途：把下面的指令交給原本製作教材的 Claude，或其他能讀取專案的 AI，補齊後續維護需要的資訊。

這份文件保存的是可複製的任務指令；下列維護說明、驗證文件與交接文件是執行任務時需要建立或補全的交付物。

## 如何使用

讓 AI 取得這個儲存庫的最新版程式碼，然後貼上：

> 請讀取 docs/AI-MAINTENANCE-PROMPT.md，執行其中「文件補齊指令」，將文件實際寫入專案，完成後回報修改清單與驗證結果。

如果使用一般聊天介面，請提供儲存庫內容或相關檔案；若 AI 無法讀取連結，就貼上下方完整指令，並附上需要的原始碼。原始設計對話若仍可取得，也一併提供。

## 文件補齊指令

```text
請替這個儀器原理網站補齊「讓不同 AI 都能接手」的維護文件，
並把文件實際存進專案。

先讀取目前最新版程式碼、AGENTS.md、README.md、INSTRUMENTS.md，
再參考這段對話中仍可取得的設計背景。本次以補齊文件為範圍，
保留現有網站外觀、功能和公開網址。

請完成：

1. 更新 AGENTS.md
作為所有 AI 共用的維護規則。保留使用者已確認的設計偏好，
寫明修改流程、驗證方式，以及什麼情況需要同步更新文件。
詳細技術內容放在其他文件，這裡提供索引即可。

2. 補齊各儀器的維護說明
分別建立 lcq/MAINTENANCE.md、gc-ms/MAINTENANCE.md、
uv-vis/MAINTENANCE.md，說明：
- 主要程式區塊、實際函式與變數名稱。
- 3D 模型、座標、尺寸、材質、燈光的設定位置。
- 光路或粒子動畫、科學計算、圖譜之間如何連動。
- 操作介面、狀態、導覽、鏡頭與字幕如何協作。
- 錄影或匯出功能若存在，如何使用及有哪些限制。
- 修改文字、模型、光路、公式、鏡頭時，應從哪裡下手。

請解釋重要設計原因與相依關係，不必逐行翻譯程式。
引用檔案路徑及函式名稱，避免只用容易變動的行號。

3. 補齊 INSTRUMENTS.md 的科學依據
區分原廠規格、文獻資料、計算推估與教學示意。
記錄公式、單位、參數來源、原始資料連結與可確認的頁碼。
找不到依據的項目標成「待確認」，不要替既有程式編造理由。

4. 建立 docs/VALIDATION.md
整理可重複執行的檢查命令，以及各儀器的人工操作步驟、
預期結果、重要數值案例。涵蓋導覽、參數調整、圖譜、
返回連結與手機排版。
現有檢查無法涵蓋的部分要說清楚。

5. 建立 docs/HANDOFF.md
記錄目前完成狀態、已知問題、待確認資料及下一步。
標明檢查日期與對應版本，區分已驗證和未驗證事項。

最後檢查文件中的路徑、函式、命令是否真的存在。
交付時列出新增或修改的文件，以及尚缺哪些資料。
```

## 文件補齊後的日常交接指令

每次交給其他 AI 維護時，在具體需求前加上：

```text
請先讀 AGENTS.md、README.md、docs/HANDOFF.md，
以及本次涉及儀器的 MAINTENANCE.md，再進行修改；
完成後同步更新受影響的文件，回報實際驗證結果。
```

共用規則集中維護在 `AGENTS.md`。其他工具專用的指令文件應指向同一份規則，避免重複保存後產生矛盾。
